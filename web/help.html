From zero to the leaderboard

Follow these six steps for your first submission. Code in any editor and any language, then send the result with the arena command.

1Install arena

curl -fsSL https://raw.githubusercontent.com/hugoocoto/runtime-arena/main/install.sh | sh
arena --version
irm https://raw.githubusercontent.com/hugoocoto/runtime-arena/main/install.ps1 | iex
arena --version

The installer checks the download against the release checksums. You can also get an archive from the releases page.

2Create your account

You need the event code from the organiser. Sign up in your terminal, or use the join page and then log in.

arena signup https://<domain>

Signed up on the join page, or on another computer?

arena login https://<domain>

Certificate error on a LAN event?

Trust the event's certificate once. Compare the fingerprint it shows with the one from the organiser, then run signup or login again.

arena trust https://<domain>

arena remembers the server and your login, so later commands need no address. It keeps a token for this device and sends your password only when you log in.

3Read the problem

List the round, then open a problem by its short name. This example uses a problem called sum.

arena round
arena problem sum --samples samples

--samples samples saves each sample as NAME.in and NAME.out in a folder called samples, so you can test before you submit.

4Write and build

The judge runs a Linux x86-64 executable or a script that starts with #!. Pick your language.

No build step and no Docker. Keep the #! line at the top.

#!/usr/bin/env python3
import sys

numbers = map(int, sys.stdin.buffer.read().split())
next(numbers)
print(sum(numbers))

Needs Docker. This writes an executable called sol.

arena build -- gcc -O2 -o sol solution.c

Needs Docker. This writes an executable called sol.

arena build -- g++ -O2 -std=c++20 -o sol solution.cpp

Needs Docker. The executable lands in target/release/solution.

arena build -- cargo build --release --bin solution

Needs Docker. This writes an executable called sol.

arena build -- zig build-exe solution.zig -O ReleaseFast -femit-bin=sol

arena build compiles inside the judge's environment, so your program links against the same libraries. On Apple Silicon it runs under emulation. The image is large, so run arena pull before the contest to download it.

5Submit

Give the problem, your executable and your source code. The source is required and is kept for review.

arena submit sum solution.py --src solution.py
arena submit sum sol --src solution.c
arena submit sum sol --src solution.cpp
arena submit sum target/release/solution --src src
arena submit sum sol --src solution.zig

arena follows the judging and prints the verdict. Check past results at any time:

arena submissions
arena submissions 42
  • The organiser sets a wait between your submissions. It applies across all problems.
  • The executable can be up to 64 MiB and the source up to 16 MiB.

6Watch the board

Open live boards and charts in your terminal, or use the web leaderboard.

arena board

In the terminal board, 1 to 5 or Tab switch between time, memory, time against memory, rank over time and your submissions. Left and Right change the problem. Q quits.

Verdicts

VerdictWhat to do
acceptedEvery test passed. You are on the board. Now make it faster or leaner.
wrong answerCompare your output with the samples, including edge cases and output format.
time limit exceededUse a faster algorithm or faster input and output.
memory limit exceededStore less, or process the input as a stream.
output limit exceededYour program printed too much. Look for debug output or an endless loop.
runtime errorYour program crashed or exited with an error. Return exit code 0 and check bounds.
judge errorThe judge failed, not your code. Tell the organiser, who can judge it again.

How ranking works

  • Time is the CPU time of your slowest test. Memory is your highest peak across tests.
  • Each test can run several times, and the best time and memory count.
  • Fastest uses your accepted run with the lowest time. Ties go to lower memory, then the earlier submission.
  • Leanest uses your accepted run with the lowest memory. Ties go to lower time, then the earlier submission.
  • A worse later submission does not replace your best run.
  • A frozen board hides submissions made after the freeze. Everything appears when the round ends.

Fix a problem

wait N s before submitting again
The wait between submissions is still running. Try again after N seconds.
no round is running
Submissions open when the organiser starts the round and close when it ends.
problem NAME is not in this round
Run arena round and copy the problem's short name.
executable is not for Linux x86-64
Build with arena build -- ..., or submit a #! script.
NAME is not installed on the judge
Your #! line names a program the judge lacks. Use python3 or build an executable.
The source archive is over 16 MiB
Point --src at your source files, not at a folder of build output.
wrong name or password
Check your username. If you forgot your password, ask the organiser to reset it.
wrong event code
Ask the organiser for the current code and enter it exactly.
Works on my machine, fails on the judge
Compile with arena build so your program uses the judge's libraries. Read input from standard input and print to standard output.
